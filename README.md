# Проект VK Smart Catch-Up (Умный дайджест уведомлений)

## Проблема
Текущая ситуация: активный
пользователь получает десятки уведомлений в день. Если человек был оффлайн, 
его шторка уведомлений превращается в информационную свалку
из сообщений, лайков и постов. Это вызывает стресс и приводит к
тому, что пользователи просто смахивают все пуши не глядя или отключают
уведомления. Текущее решение в виде хронологического списка не позволяет быстро
вникнуть в суть пропущенного.
## Заказчик
Заказчик — команда уведомлений ВКонтакте.
## ЦА
Активные пользователи ВКонтакте с высоким потоком входящих событий, которые
периодически выпадают из онлайна на несколько часов.

## MVP
### Функционал
- генерация данных, имитирующая получение уведомлений. Список возможных ивентов: уточнить...
- фронтенд получает данные от бэкенда за 200мс.
- фронтенд отображает дайджест в виде карточек сообщений.
- на фронтенде есть отдельная страница для генерации (что-то типа админ панели/Playground) одного или сразу нескольких уведомлений.
- фронтенд адаптируется под размер экрана.
- бекенд отдаёт данные фронтенду асинхронно: не ждёт окончания работы модели.
- бэкенд берёт данные для фронтенда из кэша (или очереди, или бд?).
- бэкенд принимает данные от генератора и формирует из них блоки (с определённым лимитом времени).
- бекенд распределяет данные из блока по кластерам (есть список важных ивентов, которые должны отображаться в оригинальном виде).
- мл модель занимается суммаризацией кластеризованных данных.
- кластеры хранятся в бд.
- мл модель легко заменяется.
- при отключении мл модели бэкенд должен ... (выдавать только важные сообщения, так как они не зависят от мл?).
- сервис должен поддерживать стандартную авторизацию и через вк.
- для авторизации используется jwt с возможностью рефреша.
- мл модель должна игнорировать инъекции, которые могут попасться в уведомлениях.
- кэш должен быть постоянно актуальный и прогретый.
- возможность страницы с настройками? (какие типы уведомлений считать важными/выбор темы/привязка акка/настройка таймера).
- метрики сервисов в графане.
### Архитектура
2 контура (синхронный и асинхронный)
Асинхронный контур:
1. Сервис генерации уведомлений.
2. Сервис получения данных и упаковки в бакеты + сохранение в очередь.
3. Сервис кластеризации и суммаризации + сохранение в кэш.

Синхронный контур:
1. Сервис, который по запросу фронта забирает данные из кэша.
2. Сервис авторизации.
3. Фронт.

обязательна нужна очередь (RabbitMQ) (скорее всего, даже 2 очереди), очередь накапливает уведомления и отдаёт их по таймеру (cron).
мл модели: для суммаризации (найти готовую модель); для кластеризации (можно попробовать без неё, если создать группы вручную); для генерации данных (можно использовать простой фэйкер)
